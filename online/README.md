# SSAR Rider — ระบบออนไลน์และทริปเมืองเซลตี้

ตัวเกมอยู่บน GitHub Pages ที่ https://coldwarth-ship-it.github.io/road-safety-app/game/index.html และใช้ Supabase โปรเจกต์ `selohymkkwvldhtohtbm` เก็บคะแนน แยกตารางขึ้นต้น `ssar_` จากเว็บไซต์จุดเสี่ยง

## เชื่อม Supabase ก่อนเผยแพร่
1. รัน `supabase/migrations/001_game.sql` ใน SQL Editor ของโปรเจกต์ที่เลือก ชื่อตารางขึ้นต้น `ssar_` แยกจากงานอื่น
2. Deploy Edge Function `game-api` พร้อม `scoring.ts` ใช้ `verify_jwt = false` ตาม config เพราะฟังก์ชันตรวจ token ผู้ใช้เองด้วย `auth.getUser` ทุกคำขอ
3. ตั้ง secret `GAME_ALLOWED_ORIGINS` เป็น origin HTTPS ของเว็บเกม เช่น `https://ชื่อเว็บ` คั่นหลาย origin ด้วยจุลภาค ห้ามใช้ wildcard
4. ใช้ secret server `SUPABASE_SECRET_KEY` หรือ `SUPABASE_SERVICE_ROLE_KEY` เฉพาะฝั่ง Edge Function ไม่ใส่ใน HTML
5. เปิด Anonymous sign-ins ผู้เล่นใส่ชื่อแล้วระบบสร้างตัวตนอัตโนมัติ ไม่ใช้ฟอร์มอีเมลหรือระบบย้ายเครื่อง
6. ก่อนสคริปต์หลักใน HTML ใส่ `window.SSAR_CLOUD = { url: "URL ของโปรเจกต์", key: "publishable key" };` ด้วย `<script>` แยก กุญแจ public ใช้กับ RLS ไม่ใช่กุญแจผู้ดูแล
7. เปิดเว็บ HTTPS ทดสอบเริ่มรอบ ส่งรอบ อ่านอันดับ เลือกสีรถ และส่งรอบเดิมซ้ำโดยคะแนนไม่เพิ่ม

## ทริปและภาพเล่าเรื่อง
- ทริปจบที่ 9,000 คะแนน ต้องจอดช่องส่งพัสดุ 2 วินาที จึงแสดงภาพส่งของ ภาพขอบคุณ และสรุปคะแนน
- จุดพัก 1,500 / 3,000 / 4,500 / 6,000 / 7,500 จอด 2 วินาทีได้หัวใจหนึ่งดวง สูงสุดสามดวง ครั้งเดียวต่อจุด ขับผ่านไม่รับหัวใจ แต่ยังเลือกทางได้
- หลังการ์ตูนพัก ผู้เล่นเลือกทางชุมชนหรือสายหลัก และกดไปต่อเอง โลกและเวลาเกมหยุดระหว่างการ์ตูน/เลือกทาง
- ระยะทางชุมชนหาร 4 และสายหลักหาร 8 เพื่อคำนวณคะแนนระยะทาง เส้นทางยาวจึงใช้ระยะประมาณสองเท่า และเกิดอุปสรรคน้อยกว่า ไม่มีคะแนนจากความเร็ว
- metrics รุ่น 5 ส่งระยะทางทั้งสองเส้นทาง จำนวนหัวใจที่ได้รับ และสถานะส่งทริปสำเร็จ Server ตรวจระยะรวม เวลาสูงสุด หัวใจสูงสุด และคำนวณใหม่ คะแนนทริปไม่เกิน 9,000 รุ่น 4 เดิมยังใช้สูตรเดิม
- ภาพ WebP แปดรูปอยู่ใน `game/assets` สคริปต์ `game/story-trip.js` ต่อระบบทริปกับเกมเดิม โหลดภาพถัดไปทีละรูป
- ทดสอบด้วย Node 24: `node game/tests/trip.test.cjs` จากราก repository

## ดูหลังบ้าน
เปิด Supabase Dashboard → Table Editor → `ssar_rounds` เพื่อดูผลรายรอบ: `nickname`, `score`, `created_at`, `metrics` (ระยะทาง เหตุปลอดภัย การชน หัวใจ และเส้นทาง)
ตาราง `ssar_profiles` เก็บคะแนนสะสมและคะแนนดีที่สุด ส่วน `ssar_sessions` เก็บรอบที่เริ่ม/ส่งแล้ว เกมไม่แสดงข้อมูลผู้เล่นรายอื่นนอกเหนือจากชื่อเล่นกับคะแนนบนอันดับ

## การบันทึก
- รอบออนไลน์ต้องเริ่มผ่าน server ก่อนเล่น ใช้ UUID ต่อรอบและตรวจผู้ใช้เจ้าของรอบ
- เมื่อจบรอบ บันทึกผลรอส่งในเครื่อง แล้วส่งผ่าน `game-api` เมื่อเชื่อมต่อได้
- Server คำนวณคะแนนใหม่จากระยะ เหตุการณ์ปลอดภัย โบนัสส่งของ และคะแนนหัก ไม่ใช้คะแนนรวมที่ client ส่งมา
- บันทึกผลและเพิ่มความก้าวหน้าในธุรกรรมเดียว ล็อกรอบและ profile จึงไม่เพิ่มคะแนนซ้ำเมื่อ retry
- การเลือกสีรถ/ชุดเก็บผ่าน server ทุกสีเปิดตั้งแต่แรก ไม่ใช้แต้ม
- คะแนนก่อนเชื่อมระบบเป็นผลฝึกในเครื่อง ไม่ย้ายเข้าอันดับออนไลน์อัตโนมัติ
- อันดับรายสัปดาห์เริ่มวันจันทร์ 00:00 เวลาไทย แสดงชื่อเล่นและคะแนนดีที่สุดต่อบัญชี

## ขอบเขตการตรวจโกง
ตรวจระยะสูงสุด เวลา จำนวนเหตุการณ์ stage ที่ปลดล็อก และเจ้าของรอบ ช่วยลดการส่งคะแนนผิดปกติ แต่ไม่ได้ยืนยันการขับขี่ทุกเฟรม ผู้เล่นที่แก้โค้ด client ยังอาจสร้างผลที่ผ่านขอบเขตนี้ได้ หากจัดแข่งขันจริงควรเพิ่ม seed และ event log ที่ตรวจย้อนหลังฝั่ง server

## ก่อนเปิดจริง
- ทดสอบบนโทรศัพท์ Android และ iPhone ทั้งสองแนวหลังเปลี่ยนเวอร์ชัน
- ทดสอบความดัง เสียงหยุดเมื่อพัก และเปิดปิดแรงสั่น
- ทดสอบการส่งคะแนนสำเร็จ ล้มเหลว และ retry
- ตรวจสิทธิ์ตาราง: ผู้เล่นไม่มีสิทธิ์เขียนคะแนนหรืออ่านอีเมลผู้อื่นโดยตรง
- ใช้ภาพพี่ชาร์คกี้ฝังในเกมจากไฟล์เดิม ภาพต้นฉบับมีพื้นหลังลายตารางตามไฟล์ที่มีอยู่

## กติกาพื้นผิวเสี่ยง
น้ำขังและถนนขรุขระไม่หักคะแนนหรือชีวิต ถ้าผ่านโดยไม่กดเร่งในบริเวณนั้นได้โบนัส 25 คะแนนต่อจุด หากกดเร่งจะไม่มีโบนัสจุดนั้น กติกาคนข้าม รถ และอุปสรรคอื่นคงเดิม

## การอัปเดตเหตุการณ์และอุปกรณ์
- `game/safety.js` ต่อจาก engine และ story-trip: เก็บพิกัดรถจริง รวมเลนอย่างต่อเนื่อง พร้อมไฟเลี้ยวก่อนเคลื่อนด้านข้าง
- จุดพักกลางทางบังคับทุก 1,500 คะแนน: กดเบรกค้าง 2 วินาที อ่านการ์ตูน เลือกเส้นทาง และกดเริ่มไปต่อเอง จบที่ 9,000
- รถพยาบาลมีคำเตือนด้านบน 3 วินาที แล้วแซงเร็วกว่าผู้เล่นอย่างน้อย 260 หน่วย/วินาที ไม่หยุดรอผู้เล่นและไม่ลบหรือพักการสร้างสิ่งกีดขวาง
- ไฟแดงมีรถข้ามแยกสองทิศ ไฟเขียวมีรถบรรทุกฝ่าไฟแดงพร้อมแตรล่วงหน้า
- สุนัข แมว งู คนและรถหลายรูปแบบ รถจานบินเริ่มสุ่มปะปนตั้งแต่ 3,000 คะแนน
- เลือกโทรศัพท์หรือคอมก่อนเริ่ม โหมดคอมใช้พื้นที่ถนนจำกัดความกว้างและคีย์บอร์ด โทรศัพท์คงการปัดและปุ่มสัมผัสทั้งสองแนว
- ทดสอบ `node game/tests/safety.test.cjs` (ต้องมี online/supabase/functions/game-api/scoring.ts ตามโครงสร้าง repository) จำลอง engine จริงครบ 9,000 ทั้งสองโหมดอุปกรณ์ ตรวจการหยุดทุกจุด เรื่องครบ 8 ภาพ และสูตรคะแนน server
- ยังต้องทดสอบสัมผัสและเสียงบน Android/iPhone เครื่องจริงก่อนใช้ในกิจกรรม

## จังหวะอุปสรรคตามความเร็ว
- สัตว์ 6 จาก 18 เหตุการณ์ปกติ (1 ใน 3) ทั้งสุนัข แมวและงู ไม่ถูกแทนที่ด้วยน้ำขังระหว่างฝน
- แยกระยะเตือนออกจากระยะเริ่มเคลื่อนไหว: เตือนก่อน แล้วเริ่มเมื่อระยะ <= clamp(ความเร็ว × 1.1 + ระยะเบรก + 30, 150, 430) เมื่อเริ่มแล้วข้ามต่อแม้ผู้เล่นเบรก
- รถหน้าเข้าเขตอุปสรรคก็เริ่มเหตุการณ์ได้ ป้องกันคิวรถติดรอเหตุการณ์ที่ยังไม่เริ่ม
- สภาพหลังฝนตกต่อจากช่วงฝน: ยังใช้ระยะเบรกถนนเปียก และสุ่มหลุม/น้ำขัง พร้อมคำเตือนหลังฝนหยุด
- รถอื่นวิ่งผ่านพื้นที่จอดพักต่อได้ ไม่ตั้งคิวหยุดจนกีดขวางช่องพักของผู้เล่น
