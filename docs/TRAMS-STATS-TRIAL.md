# ทดลองนำเข้าสถิติกรมทางหลวงจาก TRAMS

เปิด `trams-stats-test.html` ผ่านเว็บเซิร์ฟเวอร์ หน้าเดิมและข้อมูลชีทเดิมไม่ได้เปลี่ยน

## ขอบเขต

- ต้นทาง: https://datagov.mot.go.th/dataset/roadaccident
- ใช้ CSV รายปีจาก catalog API ของกระทรวงคมนาคม กรอง `หน่วยงาน = กรมทางหลวง` และ ชลบุรี ระยอง จันทบุรี ตราด
- ไม่ใช่อุบัติเหตุทุกถนน และไม่ใช่อุบัติเหตุเฉพาะไรเดอร์
- 1 ระเบียนนับเป็น 1 ครั้งตามไฟล์ต้นทาง ไม่อนุมานว่าระเบียนที่เหมือนกันคือเหตุเดียวกัน เพราะ CSV ไม่มีรหัสเหตุเฉพาะ
- สัดส่วน จยย. นับระเบียนที่จำนวนรถจักรยานยนต์ > 0 หารด้วยระเบียนทั้งหมด ไม่ใช้จำนวนรถหรือค่าเฉลี่ยร้อยละข้ามจังหวัด
- วันที่เกิดเหตุใน CSV เป็น วัน/เดือน/ค.ศ. ตรวจจากแถวที่วันมากกว่า 12 และคอลัมน์ปีที่เกิดเหตุ
- `resourceModifiedAt` เป็นค่าจาก catalog เก็บตามต้นฉบับโดยไม่สมมติ timezone หน้าทดลองแสดงเฉพาะวันที่ ส่วน `fetchedAt` เป็น UTC มี timezone และแสดงเวลาไทย

## ผลทดสอบไฟล์ปี 2569

- ระเบียนเหมือนกันทุกช่องทั้งไฟล์ 21 แถว คงไว้ตามต้นทาง; ชุด 4 จังหวัดที่เลือกไม่มีแถวซ้ำดังกล่าว

## การนำเข้าใหม่

ใช้ Python 3 มาตรฐาน ไม่ต้องติดตั้งแพ็กเกจ:

```sh
python scripts/sync_trams.py --year 2026
python -m unittest discover -s tests -p test_trams.py -v
```

สคริปต์ค้น CSV ปีที่เลือกจาก catalog โดยไม่ฝังชื่อไฟล์ที่อาจเปลี่ยน ดาวน์โหลด ตรวจ schema/ปี/ตัวเลข แล้วเขียนผลสรุป JSON แบบ atomic เมื่อสำเร็จเท่านั้น ถ้าเครือข่ายหรือข้อมูลผิดพลาดจะ exit nonzero และไฟล์ผลครั้งก่อนยังคงเดิม ข้อมูลดิบไม่ถูกบันทึกเข้าระบบเผยแพร่

ตรวจซ้ำจากไฟล์ที่ดาวน์โหลดไว้ได้:

```sh
python scripts/sync_trams.py --year 2026 --catalog /path/catalog.json --csv /path/accident2026.csv --output /tmp/trams-check.json
```

## สถานะการทำงาน

เป็นการนำเข้าทดลองสำเร็จหนึ่งครั้ง ยังไม่มี scheduler และยังไม่เปลี่ยน `loadStats()` หรือ Apps Script เดิม ปุ่มโหลดใหม่ของหน้าทดลองอ่าน JSON ที่นำเข้าแล้วเท่านั้น ไม่ได้สั่งดาวน์โหลด CSV ทางการ

ขั้นใช้งานจริง: เลือกตัวรันตามเวลา (เช่น Apps Script หรือ GitHub Actions) ทดสอบความล้มเหลวและการแจ้งเตือน แล้วค่อยเปลี่ยนหน้าสถิติเดิมให้ใช้ผลนำเข้า พร้อมสถานะข้อมูลเก่าและเวลาตรวจล่าสุด ห้ามแสดงว่าเรียลไทม์เพียงเพราะดึงได้ทุกวัน
