## ขอบเขต

- คงเมนูเดิม แผนที่ เกม ภัยพิบัติ การแจ้งจุดเสี่ยง สถิติ และบทความ
- ใช้ UI พาสเทลจากตัวอย่างที่ผู้ใช้เลือก รองรับโหมดมือถือ/คอมและพี่ชาร์คกี้
- คลังสื่ออ่านจาก Supabase เท่านั้น ไม่แสดงภาพตัวอย่างปนข้อมูลจริง
- บัญชีเจ้าของที่อนุญาตแล้ว: เพิ่มหลายภาพ จัดลำดับหน้าก่อนอัปโหลด จัดลำดับรายการ แก้ชื่อ ย้ายถังพัก กู้คืน เพิ่มอุบัติเหตุ
- ข้อมูลถนนและอุบัติเหตุยังเก็บ Google Sheets เดิม
- ไม่มีการให้สิทธิ์เจ้าของจากอีเมลที่กรอกเองและไม่มีปุ่มสมัครเจ้าของ
- Login ที่เตรียมไว้ใช้รหัสทางอีเมล ไม่เก็บ session เจ้าของถาวรข้ามการเปิดเว็บใหม่

## ติดตั้งตามลำดับ

1. ตรวจ Supabase ที่ติดตั้งอยู่จริงก่อน: ตารางสื่อ, bucket, RPC, policies, ผู้ใช้เจ้าของ และ email template
   ถ้ามี schema เดิมที่ใช้ต่างชื่อ ให้ปรับ adapter/config ให้ตรงของเดิม ไม่สร้างคลังใหม่ทิ้งข้อมูลเก่า
   SQL ที่แนบสร้าง module `road_media_items`, `road_site_owners`, `is_road_owner`, `road-media` เป็นสัญญารองรับกรณียังไม่มีของเดิมเท่านั้น
2. สำรอง definition/schema และรายการสื่อเดิมจากช่องทางจัดการของเจ้าของ
3. เมื่อยืนยันว่าใช้ schema ใหม่ได้ จึง apply SQL ทั้ง transaction ตรวจ GRANT/RLS ทุก policy รวม policy เดิมบน storage.objects ที่อาจให้สิทธิ์กว้างกว่า
   โค้ดไม่เปลี่ยน bucket เดิมที่เป็น public ให้ private เงียบ ๆ แต่จะหยุดและ rollback transaction
4. ตรวจ UID ของบัญชี Auth เจ้าของที่มีอยู่ แล้วเพิ่ม UID นั้นใน allowlist ผ่านช่องทางจัดการเท่านั้น
   ถ้ายังไม่มีบัญชีต้องให้เจ้าของจัดตั้ง/ยืนยันบัญชีก่อน ห้ามใช้บัญชีทดสอบแทนเจ้าของ
5. ตั้ง email provider/template ให้ส่งรหัส `{{ .Token }}` ไม่ใช่มีเฉพาะ Magic Link และทดสอบรับรหัสจริง
6. เพิ่ม RoadOwnerAuth.gs และแก้ฟังก์ชัน submitRiderIncident_ ใน Apps Script ตัวที่ endpoint ถนนใช้อยู่จริง
   ตรวจ doPost และ apiPostReport ทุกเส้นทางให้เรียกฟังก์ชันเดียวกัน ไม่มีเส้นทางเขียนเก่าที่ข้าม gate
7. ตั้ง Script Properties: ROAD_SUPABASE_URL เป็น URL ใน owner-config.js และ ROAD_SUPABASE_PUBLIC_KEY เป็น publishable key ของ project เดียวกัน
   ไม่ใช้ service-role key ไม่พิมพ์ token ใน log และไม่ใส่ token ใน URL
8. บันทึกรุ่น Apps Script เดิมและ deploy รุ่นใหม่โดยคง deployment URL เดิม ทดสอบอ่านจุดเสี่ยง/สถิติเหมือนเดิม
9. ทดสอบครบตามรายการด้านล่างแล้วจึง merge UI เข้า main และรอ GitHub Pages deploy สำเร็จ

## เกณฑ์ทดสอบจริงก่อน merge

- คนไม่ล็อกอินอ่านรายการที่เผยแพร่และเปิดทุกหน้าการ์ตูนได้
- คนไม่ล็อกอินและบัญชีทั่วไปเพิ่ม/แก้ไขสื่อและอุบัติเหตุไม่ได้ แม้เรียก API ตรง
- เจ้าของรับ OTP และล็อกอินสำเร็จ ตรวจสิทธิ์จากเซิร์ฟเวอร์ได้
- เจ้าของเพิ่มสื่อ 1 ภาพและการ์ตูนหลายภาพได้ ลำดับหน้าและอัตราส่วนภาพถูกต้อง
- จัดลำดับรายการแล้วรีเฟรช/เปิดอีกเครื่อง ลำดับยังคงอยู่
- ย้ายถังพักแล้วผู้ใช้ทั่วไปไม่เห็นรายการ และไม่ขอ signed URL ใหม่ของภาพนั้นได้
  signed URL ที่ออกก่อนย้ายถังพักอาจอ่านได้จนหมดอายุไม่เกิน 60 วินาที
- กู้คืนแล้วรายการและภาพกลับมา ไม่มีการลบไฟล์จริงหรือ DROP ข้อมูล
- แก้จากสองหน้าจอพร้อมกันไม่เขียนทับรายการแบบเงียบ ๆ; แจ้งให้โหลดใหม่เมื่อ version เปลี่ยน
- เพิ่มอุบัติเหตุเจ้าของได้ เข้ารอตรวจสอบ และส่งซ้ำด้วย requestId เดิมไม่สร้างเหตุซ้ำ
- ตรวจว่า public API ไม่มีตัวตนไรเดอร์ อีเมล หรือ token
- โหมดมือถือ/คอมเข้าถึงเมนูเดิมทุกเมนู แผนที่ resize ถูกต้อง ไม่มีปุ่มสาธารณะเพิ่มอุบัติเหตุ
- รายงานจุดเสี่ยงของผู้ใช้ทั่วไปยังบันทึกได้ตามเดิม
- ตรวจ service worker รุ่นใหม่และเครื่องที่มี cache รุ่นเดิม

## ผลตรวจในเครื่อง

คำสั่ง `node --test tests/owner-access.test.cjs`

ผ่านการทดสอบกฎไฟล์ การจัดลำดับ/กรองถังพัก token ขาด/ผิด/หมดอายุ/anonymous/non-owner, การปิดก่อนแตะชีท, สูตร spreadsheet injection และ deduplication เมื่อส่งซ้ำ
ผลนี้ใช้ mock ภายนอก ไม่แทนการยืนยัน RLS หรือการ deploy จริง

Browser QA: Dashboard อ่าน 110 จุดได้ และแสดงยอดชีทสถิติ 8,423 หลังเพิ่มการโหลดสถิติเมื่อเปิดหน้า
หน้าเจ้าของซ่อนเครื่องมือจัดการก่อนเข้าสู่ระบบ
คลังสื่อยังโหลดจาก schema ที่เสนอไม่ได้ เป็นรายการค้างการติดตั้งจริง ไม่ใช่คลังสื่อว่างที่ยืนยันแล้ว
ยังไม่ทดสอบ OTP, CRUD, RLS หรือเพิ่มอุบัติเหตุกับระบบจริง

## ย้อนกลับ

ถ้า UI หลัง deploy มีปัญหา ให้ revert commit UI และ service worker เป็นรุ่นก่อนหน้าแล้วเปลี่ยนหมายเลข cache อีกครั้ง
อย่าย้อนฟังก์ชันตรวจสิทธิ์กลับไปเปิดให้สาธารณะเพิ่มอุบัติเหตุ
หาก auth มีปัญหาให้ปิดการเพิ่มอุบัติเหตุชั่วคราวแบบ fail closed; การอ่านและแจ้งจุดเสี่ยงเดิมต้องยังทำงาน
เก็บตารางและ Storage ใหม่ไว้ ไม่มีคำสั่ง DROP/ลบภาพในขั้น rollback ปกติ
การย้อน schema/Apps Script ต้องตรวจแยกจาก GitHub และต้องไม่ทำให้ข้อมูลใหม่ของผู้ใช้สูญหาย

## ข้อจำกัดที่พบ

ผู้ใช้เลือกไม่ติดตั้งปลั๊กอิน Supabase ในรอบนี้ และยังไม่มีช่องทางจัดการ Supabase/Apps Script ที่ยืนยันให้ใช้สำหรับติดตั้งจริง
จึงเตรียมโค้ด แยกสาขา และทดสอบในเครื่องก่อน ไม่อ้างว่าพร้อมใช้บนเว็บจริงจนกว่าจะผ่านเกณฑ์ข้างต้น
