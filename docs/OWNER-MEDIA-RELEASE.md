# รุ่น UI และระบบเจ้าของ — ตรวจระบบจริง 24 ตุลาคม 2569

## สถานะปัจจุบัน

ยังไม่เผยแพร่ main ข้อมูลจริงและตารางเดิมคงไว้ ไม่มีการย้ายฐานข้อมูลหรือเปลี่ยน allowlist เจ้าของ

- เข้าสู่ระบบ Supabase ผ่าน GitHub สำเร็จ ตรวจโครงการ selohymkkwvldhtohtbm แล้ว
- ตารางเดิมคือ public.sharky_media มี 8 รายการการ์ตูน และไม่มีรายการทดสอบที่ถูกเพิ่ม
- images เป็น text[] เก็บ URL เต็ม; published เป็น boolean; deleted_at ใช้ถังพัก
- bucket เดิมชื่อ sharky-media เป็น public ขนาดสูงสุด 10 MB ต่อภาพ คงการตั้งค่านี้
- ฟังก์ชัน is_road_owner ใช้ allowlist ใน road_private.site_owner ร่วมกับบัญชี auth.users ที่ยืนยันอีเมลแล้วและไม่เป็น anonymous
- allowlist เดิมมี 1 อีเมล แต่จำนวนบัญชีที่ยืนยันและตรงกับ allowlist เป็น 0 ยังไม่สร้างผู้ใช้หรือเปลี่ยนอีเมลเจ้าของ
- ฟังก์ชันจัดลำดับเดิมคือ reorder_sharky_media(p_category text,p_ids uuid[]) ใช้การล็อก/ตรวจรายการก่อนแก้
- RLS เปิดอยู่ สิทธิ์ UPDATE เดิมเป็นระดับคอลัมน์ครบแล้ว จึงไม่ต้องเพิ่มสิทธิ์

## โค้ดที่ปรับให้ตรงระบบเดิม

- site/owner-config.js ใช้ชื่อ table/bucket/RPC เดิม
- site/owner-media.js อ่าน text[] และ URL เดิม กรอง published=true/deleted_at=null สำหรับหน้าสาธารณะ
- รองรับภาพที่อัปโหลดใหม่ใน bucket เดิมและการ์ตูนจาก game/assets เดิม
- รับ URL ภาพเฉพาะ origin/prefix ที่อนุญาต ไม่ใช้ URL ภายนอกที่ไม่รู้จัก
- อัปเดต updated_at ทุกครั้งที่แก้ข้อมูล เพื่อให้ optimistic concurrency ตรวจการแก้จากสองหน้าจอได้
- ไม่มีการสร้างตารางหรือ bucket ใหม่ ไฟล์ supabase/road-owner-media.sql เป็นคำสั่งตรวจแบบอ่านอย่างเดียว
- คง UI พาสเทล เมนูเดิม พี่ชาร์คกี้ โหมดมือถือ/คอม และการแจ้งจุดเสี่ยง
- เพิ่ม/แก้ชื่อ/เรียงลำดับ/ถังพัก/กู้คืนสื่อ และเพิ่มอุบัติเหตุอยู่ในส่วนเจ้าของ
- Apps Script มีโค้ด gate ที่ต้องตรวจ token จริงกับ Auth และ RPC เดิมก่อนเขียนอุบัติเหตุ

## การซ่อนภาพและถังพัก

รายการในถังพักถูกซ่อนด้วย RLS และไม่ปรากฏในคลังสาธารณะ แต่รูปใน public bucket หรือ GitHub ที่เคยแชร์ URL แล้วยังเปิดได้ตามการตั้งค่าเดิม ไม่อ้างว่าการย้ายถังพักเป็นการเพิกถอน URL ภาพ และไม่ลบไฟล์จริงเพื่อให้กู้คืนได้

## ผลทดสอบ

1. Local tests ผ่าน 7 ชุด: กฎไฟล์/ลำดับ, URL ภาพเดิม/URL ที่ไม่อนุญาต, token ผิด/หมดอายุ/anonymous/non-owner, ปิดก่อนแตะชีท, ส่งอุบัติเหตุซ้ำไม่สร้างเหตุซ้ำ, spreadsheet formula escaping และการส่งรายงานจริงกับโหมดทดสอบ
2. SQL บน Supabase จริง: ใช้ SET LOCAL ROLE ทดสอบ anon/authenticated ที่ไม่ใช่เจ้าของ ยืนยันว่าไม่เห็นรายการซ่อนและเขียนไม่ได้ รวมทั้ง is_road_owner คืน false สำหรับ non-owner ไม่มีข้อมูลผู้ใช้ถูกเปลี่ยน; ทดสอบรายการ unpublished ชั่วคราวและยืนยันว่า rollback แล้วด้วย
3. Browser QA อ่านการ์ตูนเดิม 8 ตอน เปิดเต็มจอและไปตอนถัดไปได้; ตาราง media เดิมคงข้อมูลทั้งหมด
4. ยังไม่ได้ทดสอบ owner login/CRUD จริง เพราะยังไม่มี Auth user ที่ยืนยันตรงกับ allowlist

## งานที่ยังขวางการเผยแพร่

1. เตรียมและยืนยันบัญชี Auth ของอีเมลเจ้าของที่ตั้งอยู่เดิม ต้องทำผ่านขั้นตอนของเจ้าของ ห้ามสร้าง/เปลี่ยน allowlist เองหรือใช้บัญชีทดสอบแทน
2. ตรวจ email OTP template และทดสอบล็อกอินด้วยบัญชีเจ้าของจริง
3. ตรวจ Apps Script ที่ endpoint ถนนใช้อยู่จริง และติดตั้ง RoadOwnerAuth.gs/ตรวจทุกเส้นทาง doPost/apiPostReport ให้ผ่าน gate เดียวกัน
4. ทดสอบเพิ่มสื่อ หลายหน้า จัดลำดับ ถังพัก กู้คืน และเพิ่มอุบัติเหตุเจ้าของครบวงจร
5. Merge/deploy UI หลังผ่านทั้งหมด และทดสอบ service worker/เครื่องที่มี cache รุ่นเดิม

## การติดขัดของช่องทาง Apps Script

การเปิด https://script.google.com/home ถูก browser automatic approval review ปฏิเสธ เนื่องจากปลายทางพาไป developers.google.com ซึ่งอยู่นอกขอบเขต origin ที่อนุมัติไว้ ยังไม่ได้ลองเส้นทางเลี่ยงหรือเปลี่ยน Apps Script หลังถูกปฏิเสธ ต้องได้รับอนุมัติช่องทางที่ถูกต้องก่อนตรวจต่อ
