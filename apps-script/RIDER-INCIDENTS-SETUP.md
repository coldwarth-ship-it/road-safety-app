# แผนที่อุบัติเหตุจริง — การเชื่อมระบบเดิม

หน้าแผนที่อยู่ใน index.html เปิดจากเมนูเหนือ “แจ้งพื้นที่เสี่ยง” ใช้ zonesData เดียวกับหน้าแรก (เฉพาะจุดตรวจสอบแล้ว) และอ่าน `apiGet('rider_incidents')` ผ่าน endpoint เดิม

## ส่วนที่ยังต้องเชื่อมก่อนใช้งานจริง

โค้ด backend เดิมและ spreadsheet ID ไม่ได้อยู่ใน repository นี้ จึงยังไม่ได้แก้ Apps Script หรือสร้างแท็บในไฟล์จริง ให้ใช้โปรเจกต์ที่ให้บริการ DEFAULT_GS_URL ใน index.html หรือ endpoint ที่ตั้งค่าจริง ห้ามแทนที่ doGet เดิมโดยยังไม่ได้อ่านโค้ด

1. เพิ่มแท็บ `อุบัติเหตุจริง` ใน spreadsheet เดียวกับ `จุดเสี่ยง` โดยนำเฉพาะข้อมูลที่อนุมัติสำหรับเผยแพร่จากข้อมูลอุบัติเหตุที่เก็บอยู่แล้วมาใช้
2. แถวแรกใช้หัวคอลัมน์ต่อไปนี้:

`รหัสเหตุ | รหัสจุด | ชื่อจุด | จังหวัด | อำเภอ | ละติจูด | ลองจิจูด | Level | รายละเอียดโดยประมาณ | สาเหตุ | การป้องกัน | สถานะ`

3. เพิ่มฟังก์ชันใน RiderIncidents.gs ให้ Apps Script เดิม และเพิ่มเส้นทาง `rider_incidents` ใน doGet และ apiGetData โดยส่ง spreadsheet object เดิมเข้า `readRiderIncidents_` ผลลัพธ์ JSON ต้องมี `status: 'ok'`, `dataset: 'rider_incidents'`, `data: [...]`
4. อัปเดต deployment เดิม ทดสอบ endpoint และหน้าเว็บก่อนเผยแพร่หน้าใหม่

## กติกาข้อมูล

- หนึ่งแถวต่อหนึ่งเหตุ รหัสเหตุไม่ซ้ำกัน จำนวนครั้งนับจากเหตุที่เผยแพร่และผ่านการตรวจพิกัด/ระดับ ไม่มีคอลัมน์จำนวนครั้งให้บวกซ้ำ
- รหัสจุดเดียวกันต้องเป็นสถานที่เดียวกัน ใช้พิกัดมาตรฐานเดียวกันทุกแถวในจุดนั้น ถ้าไม่มีรหัสจุด จะรวมเฉพาะพิกัดตัวเลขตรงกัน ไม่รวมด้วยรัศมีเพื่อหลีกเลี่ยงนับเหตุคนละถนนร่วมกัน
- สถานะ `เผยแพร่` เท่านั้นที่ endpoint ส่งออก หัวคอลัมน์อื่นจะไม่ถูกส่งออก
- ไม่ใส่ข้อมูลส่วนบุคคลลงแท็บสาธารณะ ตรวจข้อความรายละเอียด สาเหตุ และการป้องกันก่อนเผยแพร่ เพราะการเลือกคอลัมน์ไม่สามารถลบชื่อหรือเบอร์ที่ปะปนในข้อความได้อัตโนมัติ
- ไม่มีข้อมูลตัวอย่างอุบัติเหตุจริงในโค้ด

| Level | เกณฑ์ | สี |
|---|---|---|
| Lessthan | ไม่บาดเจ็บ หรือบาดเจ็บแต่ไม่หยุดงาน | เขียว |
| Level 1 | บาดเจ็บหยุดงานไม่เกิน 3 วัน | เหลือง |
| Level 2 | บาดเจ็บหยุดงานมากกว่า 3–10 วัน | ส้ม |
| Level 3 | บาดเจ็บหยุดงานมากกว่า 10 วัน | แดง |
| Serious case | บาดเจ็บหนัก หรือทุพพลภาพ | ม่วง |
| Fatalities | เสียชีวิต | ดำ |

รองรับตัวสะกดเดิม `Serius case` ด้วย ระดับหนัก/เสียชีวิตให้เลือกตามเกณฑ์นั้นโดยตรง ไม่ใช้วันหยุดงานตัดสินแทน หมุดใช้ระดับสูงสุดในจุดและแสดงรายการเหตุแต่ละรายการใน popup
